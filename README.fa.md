## امکانات

### سه ابزار در یک نوار آدرس

| ابزار | کار |
| --- | --- |
| **لینک مستقیم** | هر آدرس فایل را به لینکی روی Worker خودتان تبدیل می‌کند، با قابلیت ادامه‌ی دانلود. |
| **شکارچی فایل** | یک صفحه‌ی وب را اسکن می‌کند و همه‌ی فایل‌های قابل دانلودش را فهرست می‌کند. |
| **بررسی فایل** | قبل از دانلود، نام، حجم، نوع محتوا، پشتیبانی از ادامه‌ی دانلود و تاریخ آخرین تغییر را نشان می‌دهد. |

### شکارچی فایل

- فایل‌ها را از `<a>`، `<video>`، `<audio>`، `<source>`، `<embed>`، `<link>`، `<area>`، متای `og:video` و **آدرس‌های پنهان در اسکریپت‌ها و JSON داخل صفحه** پیدا می‌کند.
- `<base href>`، لینک‌های نسبی، کاراکترهای HTML (مثل `&amp;`) را درست می‌فهمد و بخش `#` آدرس را حذف می‌کند. لینک‌هایی که ویژگی `download` دارند همیشه می‌آیند.
- **اسکن عمیق**: تا ۸ صفحه‌ی دیگر از همان سایت را هم می‌گردد؛ مناسب صفحه‌های فهرست پوشه.
- **حالت تصاویر** (اختیاری)، تا لوگو و آیکن‌ها نتایج را شلوغ نکنند.
- نتایج تکراری حذف می‌شوند و حداکثر ۲۰۰۰ لینک برگردانده می‌شود.

### فضای کار نتایج

- **دسته‌بندی** (ویدیو، صوت، فشرده، برنامه، سند، تصویر) و فیلتر فرمت با شمارش.
- **جستجو** با چند کلمه و حذف: عبارت `1080 -sample` یعنی نام شامل `1080` باشد و `sample` نداشته باشد.
- **مرتب‌سازی** بر اساس نام، فرمت یا حجم، با **دریافت تنبل حجم‌ها** (۴ درخواست هم‌زمان).
- انتخاب تکی یا همه‌ی موارد نمایش‌داده‌شده؛ فهرست‌های بلند ۳۰۰ تا ۳۰۰ تا بارگذاری می‌شوند.
- **پیش‌نمایش داخل صفحه** برای ویدیوهای MP4/WebM/MOV، فرمت‌های رایج صوتی و تصاویر، با قابلیت جلو و عقب بردن.
- برای هر مورد: کپی لینک اصلی، کپی لینک مستقیم و دستورهای آماده‌ی `curl`، `wget` و `aria2`.

### مدیریت دانلود

- فایل را مستقیم از Worker عبور می‌دهد (stream) و **`Range`** را کامل پشتیبانی می‌کند؛ ادامه‌ی دانلود و مدیرهای دانلود چنداتصالی کار می‌کنند.
- **راهبرد Referer** برای سایت‌های ضد‌هات‌لینک: اول آدرس خود سایت مقصد، بعد Referer موتور جستجو، بعد بدون Referer. می‌توانید Referer دلخواه هم بدهید.
- نام فایل درست، از جمله **نام‌های فارسی و یونیکد**، و امکان نام دلخواه.
- ریدایرکت‌ها دستی دنبال می‌شوند و هر مرحله دوباره بررسی می‌شود.

### رابط کاربری

- تم روشن، تیره یا خودکار؛ **فارسی (راست‌به‌چپ) و انگلیسی**؛ انتخاب شما در مرورگر ذخیره می‌شود.
- **حالت دسته‌ای**: تا ۳۰۰ آدرس را (هر خط یکی) بچسبانید و مثل نتایج اسکن با آن‌ها کار کنید.
- پیشنهاد آدرس‌های اخیر، و میان‌بر `/` برای رفتن به کادر آدرس.
- **PWA نصب‌شدنی** با قابلیت دریافت لینک از «Share» برنامه‌های دیگر (بسته به مرورگر).
- لینک آماده: `/?q=<url>&go=scan|info|direct`.

## شروع سریع

فقط یک [حساب رایگان Cloudflare](https://dash.cloudflare.com/sign-up) لازم دارید. چیزی برای نصب نیست.

### روش اول: داشبورد Cloudflare (حدود ۲ دقیقه)

1. به **Workers & Pages → Create → Create Worker** بروید، نام بدهید و Deploy کنید.
2. روی **Edit code** بزنید، همه‌چیز را با محتوای [`worker.js`](worker.js) جایگزین کنید و **Deploy** را بزنید.
3. آدرس `*.workers.dev` را باز کنید.

### روش دوم: ابزار Wrangler

</div>

```bash
git clone https://github.com/<your-username>/edgefetch.git
cd edgefetch
npx wrangler login
npx wrangler deploy
```

<div dir="rtl">

فایل `wrangler.toml` حداقلی:

</div>

```toml
name = "edgefetch"
main = "worker.js"
compatibility_date = "2025-01-01"

# [vars]
# ALLOWED_HOSTS = "example.com,cdn.example.org"
```

<div dir="rtl">

اجرای محلی: `npx wrangler dev`

## تنظیمات

### متغیر محیطی

| متغیر | نمونه | توضیح |
| --- | --- | --- |
| `ALLOWED_HOSTS` | `example.com,cdn.example.org` | اختیاری. پروکسی، بررسی و اسکن را فقط به این دامنه‌ها **و زیردامنه‌هایشان** محدود می‌کند. برای هر نصب عمومی قویاً توصیه می‌شود. |

آن را در داشبورد (**Settings → Variables and Secrets**) یا در `wrangler.toml` بخش `[vars]` تنظیم کنید.

### شیء `CONFIG`

ثابت‌های ابتدای `worker.js` را ویرایش کنید:

| کلید | پیش‌فرض | توضیح |
| --- | --- | --- |
| `title_fa` / `title_en` | – | نام برنامه به هر زبان. |
| `color` | `#e74c3c` | رنگ اصلی رابط. |
| `maxLinks` | `2000` | حداکثر لینک در هر اسکن. |
| `scanTimeoutMs` | `20000` | مهلت دریافت صفحه. |
| `infoTimeoutMs` | `15000` | مهلت بررسی فایل. |
| `maxRedirects` | `5` | حداکثر تعداد ریدایرکت. |
| `deepMaxPages` | `8` | تعداد صفحه‌های اضافه در اسکن عمیق. |

فرمت‌هایی که شکارچی می‌شناسد در آرایه‌های `FILE_EXTS` و `IMAGE_EXTS` هستند.

## نحوه‌ی استفاده

1. آدرس را بچسبانید (حتی `example.com/file.zip` بدون `https://`) و یک عملیات را انتخاب کنید.
2. **لینک مستقیم**: کپی، باز کردن، اشتراک‌گذاری، پیش‌نمایش یا کپی دستور `curl` / `wget` / `aria2`.
3. **شکارچی فایل**: فیلتر، مرتب‌سازی، انتخاب و سپس خروجی گرفتن.
4. **تنظیمات پیشرفته** (زیر کادر آدرس): Referer دلخواه، نام فایل دلخواه (فقط لینک تکی)، اسکن عمیق، شامل تصاویر. Referer و گزینه‌های اسکن عمیق و تصاویر ذخیره می‌شوند.
5. **حالت دسته‌ای**: با دکمه‌ی 📚 بالای کادر عوض کنید، هر خط یک آدرس بگذارید و *بارگذاری فهرست* را بزنید.

## فرمت‌های خروجی

خروجی روی موارد انتخاب‌شده اعمال می‌شود، و اگر چیزی انتخاب نشده باشد روی همه‌ی موارد نمایش‌داده‌شده. اول **لینک اصلی** یا **لینک مستقیم** (از طریق Worker شما) را انتخاب کنید.

| فرمت | فایل | استفاده |
| --- | --- | --- |
| فهرست متنی | `links.txt` | هر مدیر دانلودی که فهرست قبول کند. |
| ورودی aria2 | `aria2-input.txt` | `aria2c -i aria2-input.txt -c -x16 -s16` (با نام خروجی). |
| اسکریپت wget | `download-wget.sh` | `sh download-wget.sh` |
| اسکریپت curl | `download-curl.sh` | `sh download-curl.sh` |
| پلی‌لیست M3U | `playlist.m3u` | VLC، mpv و پخش‌کننده‌های دیگر. |
| JSON | `links.json` | اسکریپت و اتوماسیون. |
| CSV | `links.csv` | اکسل (با BOM یونیکد و ایمن در برابر تزریق فرمول). |

نام فایل‌های تکراری یکتا می‌شوند و در اسکریپت‌ها به‌صورت ایمن quote می‌شوند.

## مرجع API

همه‌ی مسیرها `GET` هستند. خطاها به‌صورت `{ "error": "پیام" }` با کد HTTP مناسب برمی‌گردند.

### `GET /?url=<target>`  (معادل: `/dl?url=<target>`)

فایل مقصد را از Worker عبور می‌دهد. `HEAD` پشتیبانی می‌شود و هدرهای `Range`، `If-Range`، `If-None-Match` و `If-Modified-Since` به مبدأ فرستاده می‌شوند.

| پارامتر | توضیح |
| --- | --- |
| `url` | **الزامی.** آدرس مطلق `http(s)` (URL-encode شده). |
| `ref` | Referer دلخواه برای ارسال به مبدأ. |
| `name` | نام فایل دانلودی را جایگزین می‌کند (پاک‌سازی می‌شود). |
| `inline=1` | صوت، ویدیو و تصاویر رایج را برای پخش درون‌صفحه‌ای برمی‌گرداند. بقیه‌ی انواع، و هر چیز شبیه HTML، همیشه به‌صورت دانلود فرستاده می‌شود. |

### `GET /api/info?url=<target>[&ref=<referer>]`

</div>

```json
{
  "url": "https://example.com/files/report.zip",
  "filename": "report.zip",
  "size": 12345678,
  "type": "application/zip",
  "resumable": true,
  "lastModified": "Wed, 01 Jan 2025 00:00:00 GMT"
}
```

<div dir="rtl">

اگر سرور حجم را اعلام نکند `size` برابر `null` است.

### `GET /api/extract?url=<page>[&ref=<referer>][&deep=1][&img=1]`

</div>

```json
{
  "links": ["https://example.com/files/movie.mkv"],
  "isFile": false,
  "title": "Page title",
  "pages": 1,
  "truncated": false,
  "url": "https://example.com/page"
}
```

<div dir="rtl">

اگر خود آدرس یک فایل باشد، پاسخ `{ "links": [], "isFile": true, "url": "..." }` است.

## امنیت

EdgeFetch از طرف بازدیدکنندگان آدرس دلخواه را دریافت می‌کند، پس دفاعی ساخته شده است:

- فقط `http` و `https`؛ آدرس‌های دارای نام‌کاربری/رمز، `localhost`، `.local`، `.internal`، نام‌های بدون نقطه و آدرس‌های IPv6 مستقیم رد می‌شوند.
- بازه‌های خصوصی، loopback، link-local، CGNAT، آزمایشی، multicast و رزرو IPv4 بسته‌اند، و همچنین نام دامنه‌ی خود Worker (برای جلوگیری از حلقه).
- **هر مرحله‌ی ریدایرکت دوباره بررسی می‌شود**؛ ریدایرکت به آدرس‌های داخلی رد می‌شود.
- پاسخ‌های HTML، SVG، XML، JavaScript و JSON **هرگز به‌صورت صفحه** از دامنه‌ی شما سرو نمی‌شوند و به‌صورت دانلود (`application/octet-stream`) فرستاده می‌شوند. پاسخ‌های پروکسی‌شده هدر `Content-Security-Policy: sandbox` و `X-Content-Type-Options: nosniff` هم دارند.
- برنامه‌ی وب CSP سخت‌گیرانه، `X-Frame-Options: DENY`، `Referrer-Policy: no-referrer` و `noindex` دارد. APIهای JSON هدر CORS باز نمی‌فرستند.
- فایل‌های CSV از اجرای فرمول در اکسل جلوگیری می‌کنند و در اسکریپت‌های shell نام فایل‌ها ایمن quote می‌شوند.
- `ALLOWED_HOSTS` Worker را از یک پروکسی عمومی به ابزاری خصوصی برای چند سایت مشخص تبدیل می‌کند.

> **نکته:** بررسی‌ها بر پایه‌ی نام دامنه و آدرس‌های IP مستقیم هستند. Worker نمی‌تواند پاسخ DNS را بررسی کند و روی لبه‌ی Cloudflare اجرا می‌شود، نه داخل شبکه‌ی شما، که دسترسی مهاجم را محدود می‌کند. این بررسی را «لایه‌ی دفاعی اضافه» بدانید، نه جایگزین کنترل دسترسی.

اگر نصب شما عمومی است، جلوی آن محافظت اضافه بگذارید، مثلاً [Cloudflare Access](https://developers.cloudflare.com/cloudflare-one/policies/access/) یا یک [قانون Rate Limiting](https://developers.cloudflare.com/waf/rate-limiting-rules/).

## محدودیت‌ها

- تابع محدودیت‌های Workers در پلن Cloudflare شما است (زمان CPU، تعداد subrequest در هر درخواست، مدت درخواست). اسکن عمیق و تلاش مجدد با Referer از subrequest بیشتری استفاده می‌کنند.
- شکارچی، HTML سمت‌سرور و اسکریپت‌های داخل صفحه را می‌خواند. صفحه‌هایی که لینک‌هایشان را بعد از بارگذاری با جاوااسکریپت می‌سازند، یا پشت چالش ربات یا ورود به حساب هستند، قابل اسکن نیستند.
- مانیفست‌های `.m3u8` و `.mpd` فهرست می‌شوند، اما پخش جریان‌های چندقطعه‌ای درون‌صفحه‌ای پشتیبانی نمی‌شود.
- مرورگر فقط فرمت‌هایی را که خودش پشتیبانی می‌کند پیش‌نمایش می‌دهد (MKV، AVI و مانند آن‌ها فقط دانلود می‌شوند).
- سایت‌هایی که IPهای Cloudflare را مسدود کرده‌اند، با هر هدری درخواست را رد می‌کنند.

## توسعه

</div>

```bash
npx wrangler dev        # اجرای محلی
npx wrangler deploy     # انتشار
```

<div dir="rtl">

کل پروژه یک فایل `worker.js` است: ابتدا رشته‌ی رابط کاربری و بعد کد سرور. هنگام ویرایش رابط، یادتان باشد که داخل یک Template Literal جاوااسکریپت است؛ پس در اسکریپت و CSS صفحه از بک‌اسلش، بک‌تیک و `${…}` استفاده نکنید (کاراکترهای خاص را با `String.fromCharCode` بسازید).

مشارکت خوش‌آمد است. برای تغییرات بزرگ، اول یک Issue باز کنید.

## استفاده‌ی مسئولانه

EdgeFetch را فقط برای محتوایی به کار ببرید که حق دسترسی و دانلودش را دارید، و قوانین سایت‌های مقصد و Cloudflare را رعایت کنید. نحوه‌ی راه‌اندازی نصب خودتان بر عهده‌ی خودتان است؛ آن را با `ALLOWED_HOSTS` و کنترل دسترسی محدود کنید و برای عموم باز نگذارید.
